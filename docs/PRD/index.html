PRD란 무엇일까요?

PRD는 우리가 만들 웹앱의 목적과 기능을 정리한
제품 요구사항 문서입니다.

쉽게 말하면
“무엇을 만들 것인지 먼저 정리하는 웹앱 설계도”입니다.

🎯

문제를 분명하게

무엇이 왜 불편한지부터 짚고 넘어갑니다.

🧩

기능을 선택하게

다 만들지 않고, 먼저 만들 것을 고릅니다.

🤖

AI에게 정확하게

Claude가 헷갈리지 않도록 요구사항을 전합니다.

기획은 이런 순서로 진행됩니다

  1. 아이디어
  2. 문제
  3. 사용자
  4. 기능
  5. MVP
  6. UI
  7. PRD

내 웹앱의 설계도를 만들어볼까요?

작성한 내용은 이 브라우저에 자동으로 저장됩니다.

STEP 1 · IDEA

무엇을 만들고 싶은가요?

만들고 싶은 웹앱을 한 문장으로 정리해 봅시다.

STEP 2 · PROBLEM

어떤 문제를 해결하나요?

이 웹앱이 없으면 어떤 점이 불편한지 직접 적어 봅시다.

누가, 언제, 왜 불편한지까지 적으면 더 좋은 기획이 됩니다.

STEP 3 · USER

가장 먼저 사용할 사람은 누구인가요?

모두를 위한 앱이 아니라, 첫 번째 사용자 한 명을 정합니다.

STEP 4 · USER FLOW

어떤 순서로 사용하나요?

사용자가 웹앱을 사용하는 과정을 순서대로 적습니다. 최소 3개 이상 작성합니다.

예시

1. 앱을 연다.
2. 일정을 등록한다.
3. 등록한 일정을 확인한다.
4. 완료한 일정을 체크한다.

STEP 5 · FEATURES

어떤 기능이 필요할까요?

필요한 기능을 직접 적어 봅시다. 최소 5개 이상 작성합니다.

예시

일정 등록
일정 삭제
완료 체크
마감일 정렬
브라우저 저장
검색
알림

Claude 활용 예시

아래 프롬프트를 참고해 Claude에게 아이디어를 얻어 보세요.

예시 프롬프트

나는 [프로젝트명]이라는 웹앱을 기획하고 있어.

주요 사용자는 [사용자]이고,
해결하려는 문제는 [문제]야.

현재 내가 생각한 기능은 다음과 같아.
[내가 작성한 기능]

이 문제를 해결하는 데 도움이 될 수 있는
추가 기능 아이디어를 5개만 제안해줘.

아직 PRD를 작성하지 말고
기능 이름과 필요한 이유만 간단히 알려줘.

Claude가 제안한 기능을 전부 사용하는 것이 아니라, 내가 필요하다고 판단한 기능만 위 목록에 추가합니다.

STEP 6 · MVP

기능 카드를 직접 분류해 보세요

카드를 마우스로 끌어서 옮깁니다. 이번에 만들 기능은 최대 5개까지 담을 수 있습니다.

이번에 만들 기능

0 / 5

가장 먼저 만들 핵심 기능만 남깁니다.

나중에 만들 기능

0개

지금은 만들지 않지만 기록해 두는 기능입니다.

💡 카드를 끌어다 놓으세요. 키보드를 사용한다면 카드를 선택한 뒤 Enter 또는 Space 키로도 반대편으로 옮길 수 있습니다.

STEP 7 · UI

첫 화면에는 무엇이 있어야 할까요?

화면을 열었을 때 보여야 하는 요소를 골라 봅시다.

필요한 만큼 여러 개를 고를 수 있습니다.

STEP 8 · ACCEPTANCE CRITERIA

어떻게 작동하면 완성일까요?

완성되었다고 판단할 수 있는 기준을 적습니다. 최소 5개 작성합니다.

예시

빈 값은 저장되지 않는다.
등록한 일정이 목록에 나타난다.
완료 여부를 변경할 수 있다.
일정을 삭제할 수 있다.
새로고침 후에도 저장한 내용이 유지된다.

STEP 9 · PRD PREVIEW

현재 PRD를 확인하세요

지금까지 작성한 내용이 Markdown으로 정리되었습니다. 복사해서 Claude에게 검토를 받아 보세요.
